# XR Screen Lab — симулятор XR-очков для Meta Quest 3

Веб-приложение для оценки **реального углового размера** виртуального экрана RayNeo GT, GT Max и любых других очков с заданным диагональным полем зрения. Исходники — в одном `index.html`, без CDN, сторонних библиотек, учётной записи и передачи пользовательских файлов на сервер.

## Возможности

- **RayNeo GT:** диагональный FOV 46°, геометрически ~40,6° по горизонтали и ~23,5° по вертикали при формате 16:9.
- **RayNeo GT Max:** диагональный FOV 59°, ~52,5° по горизонтали и ~31° по вертикали.
- **Свой FOV:** от 20 до 95° по диагонали.
- Регулировка условного расстояния до экрана от 0,7 до 5 метров, выбор 16:9, 21:9 или 4:3.
- Три режима поведения экрана: «3DoF» (фиксация по направлению при сохранении следования за перемещением головы), «В комнате» (6DoF) и «Следует» (прикреплён к голове).
- Passthrough Meta Quest Browser через WebXR `immersive-ar`, загрузка личного изображения или видео, условная непрозрачность.
- Настройки поверх AR через DOM Overlay, если он поддерживается; в остальных случаях резервное управление контроллерами Quest.

## Как запустить именно на Quest 3

Для WebXR-сессии нужен **HTTPS-адрес**. Нельзя просто открыть файл на шлеме с диска и ожидать, что passthrough автоматически заработает. Самый простой бесплатный способ разместить это приложение:

1. На GitHub создай **новый публичный репозиторий**, например `xr-screen-lab`.
2. Нажми **Add file → Upload files** и загрузи из этого архива файл **`index.html`** в корень репозитория. Сохрани коммит.
3. Открой **Settings → Pages**, выбери **Deploy from a branch**, ветку **main**, каталог **/(root)**, затем **Save**.
4. После публикации открой на Quest в **Meta Quest Browser** адрес вида `https://ТВОЙ_ЛОГИН.github.io/xr-screen-lab/`.
5. Разреши WebXR/смешанную реальность при запросе и нажми **«Включить AR в Quest»**.

Для первоначального просмотра без шлема можно открыть `index.html` на ПК: будут доступны меню, пример окружения и приближённая визуализация размеров. **Но режим WebXR в обычном файловом просмотре работать не обязан.**

## Управление в шлеме

Если меню поверх passthrough доступно, используй ползунки и кнопки.

Если меню не отображается, пользуйся контроллерами (раскладка ориентирована на стандартное сопоставление WebXR Gamepad):

- Левый стик **влево/вправо** — уменьшить/увеличить диагональный FOV.
- Левый стик **вверх/вниз** — изменить условное расстояние.
- **Курок** — вернуть экран в центр текущего взгляда.
- **A / X** — переключить режим поведения экрана.
- **B / Y** — показать/скрыть вспомогательную панель.

Своё видео удобнее загрузить **до входа в AR**: возможность открыть файловое окно через DOM Overlay зависит от конкретного браузера. Видео остаётся на устройстве; используется локальный `blob:` URL.

## Что симулируется, а что нет

✅ **Геометрия**: размеры на заданном расстоянии рассчитаны из диагонального FOV и соотношения сторон и выводятся с WebXR-проекцией для каждого глаза.

✅ **Поведение**: фиксация направления, закрепление в комнате или экран, следующий за головой.

❌ **Не воспроизводятся** реальное оптическое поле зрения прозрачных очков, прозрачность чёрного в birdbath-оптике, Micro-OLED HDR, яркость, резкость по краям, вес и посадка очков.

❌ Не выводится живой экран Windows и не передаётся видео с ПК — только загруженные пользователем медиафайлы и встроенная демосцена. Для стриминга экрана нужна отдельная система передачи видео.

**Важно:** эти показатели описывают *угловой размер изображения*, а не полное поле зрения человека через прозрачные линзы очков. Вокруг экрана RayNeo виден реальный мир.

## Технические детали

- Чистый HTML/CSS/JavaScript, WebGL 1 и WebXR `immersive-ar`.
- AR-прозрачность достигается альфа-каналом XRWebGLLayer; камеру passthrough приложение не читает.
- Контролы по возможности доступны через WebXR DOM Overlay; поддержка определяется браузером в реальном времени.
- Нет сторонних JS-пакетов и сетевых запросов.

**Проверка:** проведена статическая проверка синтаксиса JavaScript и структуры HTML. Запуск непосредственно на физическом Meta Quest 3 здесь не выполнялся, поэтому совместимость отдельных WebXR-функций может потребовать корректировок на устройстве.
